# План подбора Артдент

Вакансии → «Создать план подбора» → название любой должности. Вопросы агента строятся по позиции и исходным данным; отдельного сценария создания под контакт-центр нет. Существующий план контакт-центра остаётся обычным планом в списке.

Внешний и внутренний брифинги используют общий чат: история прокручивается отдельно от закреплённого поля ввода, сообщение сразу показывается в ленте, на время запроса появляется индикатор ответа. Enter отправляет, Shift+Enter добавляет строку. При чтении старых сообщений новый ответ не сбрасывает прокрутку; кнопка возвращает к последним сообщениям. Итоговые требования проверяются на отдельном экране. Страницы создания плана, профиля и описания прокручиваются внутри полноэкранной оболочки.

1. HR загружает исходные материалы (PDF/DOCX/TXT) и создаёт внешнюю ссылку. Руководитель открывает её без аккаунта, разговаривает с ИИ, проверяет сводку и передаёт её HR. Ссылка содержит секрет в URL-фрагменте, который обменивается на HttpOnly-cookie и убирается из адресной строки. В базе хранится только SHA-256. Срок по умолчанию семь дней; ссылку можно отозвать. После завершения она доступна только для чтения. Для уточнений HR создаёт новое приглашение.
2. HR формирует и редактирует профиль: профессиональные требования, бизнес-результаты и наблюдаемые рабочие действия; обязательность и способ проверки каждого критерия. Утверждает профиль.
3. Существующий генератор Harly создаёт описание. HR редактирует и утверждает его, затем переходит в стандартный редактор Harly: вводный текст и разделы уже заполнены. Для связанной вакансии новый текст подставляется для проверки без изменения опубликованной страницы до сохранения. План заканчивается оформлением вакансии.
4. После появления отклика HR открывает в карточке кандидата единый блок разбора резюме с названием вакансии. Он показывает «Разбор резюме готов», «Разбор резюме устарел», «Резюме ещё не оценено», «Разбор резюме в очереди», «Разбираем резюме…», «Разбор не выполнен» или отсутствие утверждённого профиля. «Открыть результат» раскрывает разбор соответствующего отклика; «Оценить по профилю» открывает ввод резюме. Эти же действия доступны во вкладке «Оценка» и возвращают к нужному отклику в «Профиле». Разбор выполняется здесь же по утверждённому профилю и фактически сохранённому тексту вакансии. Можно использовать файл кандидата, загрузить PDF/DOCX/TXT или вставить текст. Отчёты доступны только для своего отклика, содержат цитаты и вопросы и сохраняют снимок вакансии. После изменения профиля или текста вакансии прежние разборы помечаются устаревшими. Статус вычисляется на сервере для первого отображения, а после обновления данных или нового разбора меняется сразу. При наличии истории первым открывается актуальный результат. Старые числовые оценки Harly доступны отдельно во вкладке «Оценка» в «Ранее сохранённые оценки Harly»; отсутствие такой оценки не перекрывает готовый разбор по профилю. Сервер проверяет версию профиля и вакансии до запроса и при сохранении, чтобы исключить поздний результат по изменившимся требованиям.

Загрузка PDF/DOCX/TXT непосредственно в отклик извлекает текст и сохраняет фоновую задачу в одном авторизованном серверном запросе. Общий блок «Резюме» в карточке кандидата также ставит разборы в очередь для активных доступных пользователю откликов с утверждёнными требованиями. Это не зависит от настройки числовой автооценки Harly. При вставке текста запуск остаётся отдельной кнопкой. Без утверждённых требований или читаемого текста причина показывается в интерфейсе.

Задачи `hiring_review_jobs` хранят снимок текста и ссылку на требования; SHA-256 по требованиям и тексту исключает повторный разбор того же источника. Повторная загрузка уже прикреплённого файла также проверяет актуальные требования без повторного сохранения файла. Повторная загрузка ранее оценённого файла выбирает его сохранённый результат, даже если он старше других отчётов. Новый источник отменяет незавершённую задачу предыдущего резюме. Lease и проверка токена при записи не дают отменённому/старому worker сохранить поздний результат. После закрытия страницы задача продолжает работать. Статусы обновляются каждые три секунды только при незавершённом разборе; результат доступен после повторного входа.

`after()` запускает обработчик сразу после ответа; существующий scheduler вызывает защищённый `/api/cron/hiring-reviews` раз в минуту для оставшихся задач. Одновременно обрабатывается одна задача на экземпляр базы; платный запрос ограничен 60 секундами, lease — 120 секундами. Истёкший lease позволяет восстановить работу после перезапуска, максимум три попытки восстановления. Ошибки ИИ сохраняются явно и повторяются кнопкой пользователя; файл/текст остаётся доступным. Результат, успевший сохраниться до перезапуска, используется без повторного платного запроса.

## Агент

`@openai/agents`: HiringBriefingAgent → read_source/update_brief/prepare_summary. SDK Session загружается из PostgreSQL и буферизует изменения до атомарного сохранения успешного хода. Модель берётся из настроек рабочего пространства (OpenRouter или OpenAI), OpenAIChatCompletionsModel использует существующий aiFetch с HARLY_AI_PROXY_URL. Глобальный HTTP-прокси не используется; внешняя отправка трасс SDK отключена.

Сообщение записывается до платного запроса. Durable request ID исключает повтор уже завершённого хода. Lease на плане предотвращает одновременные изменения; после сбоя/перезапуска истекает. Отмена освобождает lease и запрещает фиксацию позднего ответа. История и черновик сохраняются; можно повторить неудавшееся сообщение. Сравнение версии защищает от перезаписи из другой вкладки.

Инструменты ограничены текущим брифом. Ссылки не дают доступа к кандидатам или другим планам. POST проверяет Origin; ответы не кэшируются. Источники и текст документов считаются данными, а не инструкциями. Дословная цитата проверяется сервером, её смысл проверяет человек. Отсутствие сведений в резюме не становится отрицательной оценкой; поведение проверяется интервью или кейсом. Автоматических решений о найме нет.

## Настройки экземпляра

- HARLY_BRIEFING_INVITE_DAYS: 7
- HARLY_BRIEFING_TIMEOUT_MS: 90000
- HARLY_BRIEFING_MAX_STEPS: 5 вызовов модели за ход
- HARLY_BRIEFING_DAILY_REQUESTS: 60 попыток на план за скользящие 24 часа

Для Compose передавайте нестандартные значения в environment app. Ключ OpenRouter хранится в существующих настройках ИИ и шифруется AI_ENCRYPTION_KEY; ключ необходимо сохранять при обновлении.

Миграция 0157 добавляет фоновую очередь разбора резюме; миграции 0154–0156 добавляют состояние/отчёты, приглашения, durable inputs и lease. До обновления: резервная копия, проверка цепочки миграций; после: миграции и проверка готовности. Дополнительные сервисы не нужны.

Даты в документе противоречат друг другу и отмечены для уточнения. KPI и методика поведенческих кейсов требуют согласования. Три подготовленных резюме вымышлены; реальные имена и контакты из документа не используются.
